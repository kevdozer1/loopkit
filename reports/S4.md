# S4. Bake-off runner and report

Date: 2026-10-17. Spend: $0.

**Status: partial.** The runner, report, cost estimate and start script are built and tested, and the FakeModel dry run produced the full report and figure. The real 2-model T2 run is blocked: no key is set, so no model can be called. The full-run estimate below is therefore a projection from the real prompt sizes, not from a measured run.

## What ran

1. `loopkit/bakeoff/run.py`: `uv run python -m loopkit.bakeoff.run --config config/bakeoff.yaml [--models ...] [--tasks ...] [--repeats N] [--dry-run]`. For each model, task and repeat (a unit): T2 and T3 run rehearse-and-patch on the training seeds and score the best graph on the held-out seeds; T1 calls the model as the panel reader once per held-out seed. Per-model caps from bakeoff.yaml and the total cap go through the router ledger. A model at its cap stops with a `budget_stop` event and its remaining units are recorded as skipped. Every unit is checkpointed, and a rerun with the same `--date` skips finished units (an error, or a skip for a missing key, runs again). Models without a key are skipped up front and listed. A unit whose writer never produced a valid graph scores 0 on all its held-out seeds. Repeats never share cache entries (the repeat index is in every request hash), and held-out episodes are cached by (task, seed, graph hash) because the simulator is deterministic. The optional model (luna) is added only if every model spending up to its cap would still stay under `total_cap_usd`. A paid run prints the cost estimate before it starts. While it runs it asks Windows not to sleep, so an overnight run is not paused (the display may still turn off).
2. `loopkit/bakeoff/report.py` builds every number from the trace events: held-out pass rate with a Wilson 95% interval, mean and spread over repeats, cost per success, setup calls (writer) per unit and runtime calls per run, sim seconds per success, patch rounds to the best graph, failure classes, input and output tokens with the image share of input, spend per model against its cap, the noise note, the writer's reasoning setting as sent, model ids, run date, git commit and cache policy. It writes `results.parquet`, `report.md` (Level 1 line, Level 1.5 paragraph, Level 2 tables), `pass_vs_cost.png` (one panel per task, one dot per model, Wilson bars, direct labels, a log cost axis when costs span a decade or more) and copies report.md to `reports/bakeoff_<date>.md`.
3. `loopkit/bakeoff/estimate.py`: `uv run python -m loopkit.bakeoff.estimate [--from <bakeoff folder>]` prices the real writer, patch and reader prompts with the router's own projection. With `--from` it uses the output tokens and calls per unit measured in that run.
4. `setup/start_bakeoff.ps1`: loads env.ps1, checks the 10 GB disk floor on C: and D:, prints the estimate, runs the bake-off with stdout to `LOOPKIT_DATA\bakeoff\<date>\run.log` (stderr to `run.err.log`), then builds the report. No agent involved. It was checked with PowerShell's parser but not run, since running it would start the bake-off.
5. Tests: `tests/test_bakeoff.py` (11 tests: Wilson values, a report built from synthetic traces with every metric checked, an empty report, budget stops propagating out of the writer and the interpreter, a unit recording its budget stop, keyless models skipped and retried later, a no-graph unit failing every held-out seed, the cost estimate staying under the caps, an end-to-end dry run with resume, a dry run never scoring on the bake-off held-out seeds, and Wilson bounds exact at 0 and n).

## FakeModel dry run

`uv run python -m loopkit.bakeoff.run --config config/bakeoff.yaml --dry-run --workers 10`: all 6 models, T1 to T3, 3 repeats, training seeds 1000 to 1009 and dev seeds 600 to 619 standing in for the held-out seeds. 54 units finished in 11.5 minutes, 1,080 scored runs, $0. The report is `reports/bakeoff_2026-10-17_dry.md`, and the figure, `results.parquet` and traces are in `LOOPKIT_DATA/bakeoff/2026-10-17_dry/`.

| Task | Every model slot (FakeModel) | Wilson 95% | Sim seconds per success |
|---|---|---|---|
| T1 | 0/60 | 0% to 6% | n/a |
| T2 | 60/60 | 94% to 100% | 49.3 |
| T3 | 60/60 | 94% to 100% | 45.1 |

T1 is 0% by construction: the FakeModel reader returns the smallest answer its schema allows, not a reading of the image. T2 and T3 show what the reference graph does with this skill library on these seeds. The initial build of the report crashed at 60/60, because the Wilson upper bound rounded to just under 1 and the error bar came out negative. Both are fixed and covered by a test, and the report was rebuilt from the same traces.

A real run adds model latency: a writer call at the highest reasoning setting can take minutes (the router allows 900 s), and T2 and T3 make 1 to 24 writer calls per unit.

| cheap_open | $0.03 | $0.27 | $2 | $0.03 |
| luna (optional, included) | $0.15 | $1.32 | $1 | $0.15 |
| **Total** | **$27.16** | | | ceiling $40.27 |

Typical assumes 6000 output tokens per writer call, 3 patch rounds per unit, 1.3 attempts per writer turn and 500 output tokens per reader call. Worst case assumes all 5 patch rounds, 4 attempts per turn and every call at max_tokens. The ceiling is the sum of the caps where a model's worst case passes its cap, which the ledger enforces, and it is under `total_cap_usd` ($50). The estimate is under the total cap, so no cut is needed.

One proposal, not applied: astra's typical estimate sits at its $15 cap, so it may stop before its last T3 repeat. Raising its cap to $20 keeps the ceiling at $45.27, under $50. The config was not edited.
