# S1. Schemas, router and traces

Date: 2026-10-17. Spend: $0 (no key was set, so no paid call was made).

## What ran

1. `loopkit/schemas`: pydantic v2 models for TaskSpec (with the writer's view that hides the seed and params), SkillSpec and the catalog text, ProgramGraph, Verdict, Observation (camera images, intrinsics and extrinsics, proprioception, no object poses) and TraceEvent with one payload model per event kind. ProgramGraph validation returns every error with a code, the node and a fix hint: unknown skills and params (params are closed unless a schema opens them), refs checked against the source's output schema at their own position, refs that could be read before their source has succeeded, unbounded loops (a loop must pass through a node with `max_visits` whose failure edge leaves it), missing terminals, a success path that never reaches `done`, unreachable nodes. JSON Schemas are exported to `loopkit/schemas/json/` by `uv run python -m loopkit.schemas`.
2. `loopkit/router`: `chat(model_key, messages, images=None, json_schema=None, role=...)` with adapters for OpenRouter, Elorian (OpenAI-compatible, `alt_route` to OpenRouter when only that key is set), the System One decisions protocol (Jev and Liquid d1) and the offline FakeModel. A disk cache keyed by a request hash (the repeat index goes in through `cache_salt`), a JSONL spend ledger that reserves every HTTP attempt before it is sent and settles it afterwards, and session, per-model and total caps (`set_active_session`). Every call writes one `model_call` trace event. `uv run python -m loopkit.router.smoke` makes one small vision call per model that has a key.
3. `loopkit/traces`: `TraceWriter` (one writer per run, held by an OS lock, append-only JSONL with a per-run `seq`), `read_events`, `list_runs` and `load_runs`, which returns one pandas row per event with typed columns.
4. `config/models.yaml`: every entry checked against the OpenRouter catalogue (read 2026-10-18 00:41 UTC) and the providers' docs. Changes are listed below.
5. Review: a review workflow wrote failing repro scripts against the initial versions (router 17 findings, schemas 26 decisions with 16 repros, traces 12 findings). Fix agents applied every decision with regression tests, and independent verifiers re-ran each repro and tried to break the fixes.

## What the review changed

- Router: every attempt (retries and JSON-mode fallbacks) is reserved in the ledger before it is sent, and one that is lost to a timeout or a dropped connection stays reserved at its projection. Costs include BYOK upstream charges. The ledger lock is an OS lock. Non-finite prices and caps are refused. A provider-side generation error is never cached. The request hash covers the schema text, the destination URL and the JSON modes. Keys never reach a trace, a cache entry or an error message.
- Schemas: loop and ref rules rebuilt (see above), refs checked anywhere inside a param value, dotted paths resolved with "did you mean" hints, closed params, Verdict rules enforced (a pass has score 1 and no failure class, a failure has a class and a score below 1).
- Traces: one writer per run across processes, surrogate-safe text, a meta.json that cannot be read is moved aside instead of overwritten, typed numeric columns in `load_runs`, Windows device names and path tricks refused as run ids. The OS locks were checked on the exFAT data drive: a second process opening the same run is refused, and it opens once the holder closes.

## Second verification

Independent verifiers re-ran every router and schema repro: none of the original findings reproduce, and the suite passed (511 at the time). The traces verifier was still running at the S1 commit; the traces fixer's own run had 9 of 12 repros no longer reproducing, and the other 3 print REPRODUCED only because the intended behavior meets their checks, which stricter scripts confirmed. The router and schema verifiers also found new low-severity issues, which are open here and go to a follow-up fix round:

- Router: a lost 5xx attempt whose body carries `usage.cost` can settle below its projection (at most one attempt per call under-counted); the half-of-computed cost floor is skipped when only one token count is reported; `check_url` checks the stripped URL while adapters send the raw one (money-safe); a Jev key containing a quote or backslash survives JSON-escaped in `Response.text` and the cache; a server that echoes the key in response metadata (model, finish reason) gets it copied into the trace and cache unredacted; an absurd token count raises a non-router error after a paid call (the ledger stays at the projection).
- Schemas: the code-fence regex backtracks quadratically on a reply with a long run of spaces after a fence (32,000 spaces stall validation for about 7 s); a union param with two container branches can reject a valid nested ref; one cycle is reported per looping component, so a second loop in it costs an extra repair round; a loop through a terminal node gets a misleading second error; params under an alias key (`args`, `inputs`) are also reported missing; prose containing `{` before the graph is read as bad JSON; very long ref indexes and huge replies give unclear or very long fix text.
