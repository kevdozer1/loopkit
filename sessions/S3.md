# S3. Skills, interpreter, program writer and rehearsal (2 to 3 h, $15 cap)

Read CLAUDE.md, docs/01_architecture.md, docs/04_prior_art.md, loopkit/schemas and loopkit/sim. Build the skill library, interpreter, program writer and rehearse-and-patch loop. Spend cap: $15.

1. Skills in `loopkit/skills`. Each is a typed function whose signature and docstring generate its SkillSpec.
   - Perception: `locate(name)` and `locate_port(n)` with classical CV (color, edges, AprilTag-free template or contour fits) on camera images plus camera geometry and `nominal_geometry`. `read_panel()` asks a vision model through the router for the T1 report.
   - Motion: `move_to(pose)`, `approach(target, offset_mm)`, `retreat(mm)`.
   - Manipulation: `grasp(name)`, `release()`, `slide_into(target)`, `insert(target, speed, max_force, search)`.
   - Calibration: `dance(target, n)` makes n small offset moves near the target, measures image-space error from the wrist camera and fits a linear regression from image error to pose correction, as Kulakov does. `aligned_insert(target)` applies it.
   - `done()` and `abort(reason)` terminals.
   Skills see Observations only. Checkers may use privileged state.
2. Interpreter in `loopkit/runtime`: runs a ProgramGraph on a Backend, resolves `{"ref": ...}` params from the blackboard, enforces retries, timeouts, workspace bounds and speed limits, and emits TraceEvents. A stub `SO101Backend` that raises NotImplementedError.
3. Program writer in `loopkit/program`. Prompt: the TaskSpec, the skill catalog text, the 3 camera images, the graph format with one tiny worked example on a different task, and earlier failure summaries. Output must be ProgramGraph JSON (use json_schema mode where the adapter supports it). Validate and repair up to 3 times by sending the validator's errors back.
4. Rehearse-and-patch per docs/01_architecture.md. Failure summaries are text. Log every round as a `patch` event.
5. Tests with FakeModel: a scripted fake that returns a broken graph then a fixed one exercises repair, and a fake that improves over rounds exercises the patch loop.
6. Real run: with one frontier model (opus by default, or whichever writer key exists), run T2 on 10 training seeds from the dev range, then score on the S3 held-out seeds 500 to 519.

Acceptance: T2 at least 80% on seeds 500 to 519 within 5 rounds, every call logged. If it misses, spend at most 2 more rounds of skill fixes (skills, not prompt tricks), then report the honest number with failure classes. Try T3 once with the same model and report the number without a gate.

Commit. Write reports/S3.md with pass rate, calls and cost per round, the final graph and the next action.
