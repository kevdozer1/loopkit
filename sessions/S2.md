# S2. Sim task suite (2 to 3 h, $0, can run headless)

Read CLAUDE.md, docs/02_task_suite.md and loopkit/schemas. Build the rack_cell MuJoCo scene, the 3 tasks, their checkers and the oracle programs exactly as docs/02_task_suite.md specifies. Spend cap: $0, no model calls.

1. `loopkit/sim/rack_cell.py`: build the scene from the Menagerie Panda plus generated MJCF for rack, rails, panel, ports, LEDs, label strip and tray. `make_scene(seed)` applies the randomization. Same seed gives the same scene.
2. `SimBackend` implementing the Backend protocol from docs/01_architecture.md: `reset(seed)`, `observe()` with 3 cameras plus intrinsics and extrinsics, `act()` with Cartesian or joint targets through an operational-space or IK controller, `stop()`. Observation never contains body poses.
3. TaskSpecs T1, T2, T3 in `loopkit/sim/tasks.py`, including `nominal_geometry`.
4. Checkers in `loopkit/sim/checkers.py`, each returning a Verdict with metrics, failure_class and one evidence image.
5. Oracle programs for T2 and T3 using privileged state, and a do-nothing program.
6. A test that skills and backends cannot reach privileged state (for example, the Observation type has no pose fields and SimBackend hides `data` behind a private attribute that skills do not import).

Acceptance, with numbers in the report:
- Oracle pass rate at least 95% over 50 dev seeds for T2 and T3.
- Do-nothing scores 0 on all 3 tasks.
- Determinism test passes.
- One mp4 per task in `LOOPKIT_DATA/videos/` (oracle runs). Look at one frame from each camera and confirm the labels and LEDs are readable in `front`.

Stop rule: if T3 is not solvable after 3 contact-tuning attempts, loosen clearance to 1.0 mm, record it and move on.

Commit. Write reports/S2.md with pass rates, sim seconds per task, contact settings, the box scale and the next action.
